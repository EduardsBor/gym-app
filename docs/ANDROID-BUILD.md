# Сборка Android (GymCaptain)

Обёртка Capacitor 8 вокруг той же PWA. Сайт GitHub Pages по-прежнему отдаётся из корня репозитория (`index.html` в корне). Каталог `www/` — только выход `npm run build:web`, в git он не входит.

Публикация в Google Play, подпись релиза и регистрации — только по явной команде Эдуарда. В репозиторий нельзя класть ключи, keystore, пароли и токены.

## Идентификатор приложения

- `appId`: `app.gymcaptain`
- Можно сменить **до первой загрузки** в Google Play. После первой публикации идентификатор пакета менять нельзя.
- `appName`: GymCaptain
- Первая debug-сборка: `versionName` `1.0`, `versionCode` `1` (`android/app/build.gradle`).

## Что уже есть / что ещё нет

- Иконка и сплеш — стандартные от Capacitor. Подставить свои, когда Бизнес сдаст **B-409**.
- Подпись release/keystore и загрузка в Play — позже (**A-502**, **A-506**). Сейчас только debug APK.
- Health Connect и серверный статус подписки — позже, не в этой задаче (A-501).

## Сборка debug APK

Нужны JDK 21 (подойдёт и 17) и Android SDK (platform android-36 и build-tools, которые запросит Gradle / Capacitor 8).

```bash
# 1. Зависимости Node (один раз)
npm install

# 2. Скопировать веб-файлы в www/ и синхронизировать нативный проект
npm run build:web
npx cap sync android

# 3. Собрать debug APK
#    JAVA_HOME — JDK 17/21; ANDROID_HOME / ANDROID_SDK_ROOT — каталог SDK
cd android
./gradlew assembleDebug
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.

Встроенный service worker уже регистрируется с `.catch(()=>{})` в `app.js`. Если регистрация в WebView Capacitor не удастся, приложение всё равно работает офлайн из файлов, упакованных в APK.

## Что не входит в обёртку

- `test/`, `docs/`, `sql/`, `tools/`, `node_modules/`, `android/`
- ролики MoveKit (их нет в репозитории; они только в закрытом бакете Supabase и отдаются через `movekit-sign`)

## Уведомления (A-503)

Плагин `@capacitor/local-notifications` 8.3.1. Код — `notify.js`; на сайте/PWA он ничего не делает (`Capacitor.isNativePlatform()`), карточка «Уведомления» в «Ещё» показывается только в Android-сборке.

- **Таймер отдыха.** При старте таймера ставится одно уведомление (id 1001) на время окончания (wall-clock `tEnd`), канал `gc_rest` (важность высокая, звук и вибрация). «Пропустить», завершение или отмена тренировки — отмена. Нажатие открывает приложение на текущей тренировке. Таймер в приложении по-прежнему считает от `tEnd` и верен после возврата.
- **Напоминания о тренировке.** По умолчанию выключены. Дни недели и время (по умолчанию дни по числу тренировок в программе: 3× → Пн/Ср/Пт, 18:00). Повтор каждую неделю (`schedule.on.weekday`), id 2001–2007, канал `gc_remind`. Настройка хранится только на устройстве (`localStorage gc_remind`), в облако и историю не попадает.
- **POST_NOTIFICATIONS (Android 13+).** Спрашивается только при первом старте таймера отдыха или при включении напоминаний, после короткого пояснения. При отказе таймер в приложении работает как раньше, в настройках видно, что уведомления выключены.

### Точные будильники — выбор для проверки Google Play

- Используется **`SCHEDULE_EXACT_ALARM`** (его же объявляет плагин). На Android 14+ для новых установок он по умолчанию выключен; пользователь может включить «Будильники и напоминания» кнопкой «Разрешить точное время» в карточке «Уведомления».
- Если точные будильники не разрешены, плагин сам ставит **неточный** `setAndAllowWhileIdle` — уведомление может прийти с задержкой (в режиме Doze — до нескольких минут); в настройках показывается пояснение.
- **`USE_EXACT_ALARM` не используется**: по политике Google Play он разрешён только приложениям, чья основная функция — будильник/таймер или календарь. GymCaptain — дневник тренировок, таймер отдыха — вспомогательная функция, поэтому риск отказа при проверке. В Play Console в декларации «Exact alarms» указать: точный будильник нужен для сигнала окончания отдыха между подходами, выдаётся пользователем вручную, без него работает неточный вариант.
- Плагин также добавляет `RECEIVE_BOOT_COMPLETED` (вернуть напоминания после перезагрузки) и `WAKE_LOCK`.

### Проверить на телефоне (D-211)

1. Android 13+: первый старт таймера → пояснение → системный запрос; «Запретить» → таймер в приложении работает, в «Ещё → Уведомления» текст «Уведомления выключены…».
2. Таймер 60 с, выключить экран → уведомление со звуком/вибрацией вовремя (с разрешением «Будильники и напоминания» и без него — отметить задержку).
3. Нажатие на уведомление открывает текущую тренировку; время таймера верное после возврата.
4. Напоминания: включить, поставить время через 2 мин на сегодня → пришло; сменить день/время → старое не приходит; выключить → не приходит. Перезагрузить телефон → напоминание остаётся.
5. Язык RU/EN/LV — текст уведомлений и названия каналов на языке интерфейса.
6. Режим экономии батареи / Xiaomi/Samsung — отметить, если уведомление опаздывает.

## Sentry (A-504)

Отчёты о сбоях и ошибках — только в Android-сборке. На сайте и в PWA Sentry не запускается: инициализация требует одновременно `Capacitor.isNativePlatform()` и клиентский DSN.

**DSN в репозиторий не кладётся** (правило Эдуарда: ключи и токены в файлы не записывать). Скрипт `npm run build:web` читает переменную окружения `GC_SENTRY_DSN` и пишет gitignored файл `www/sentry-config.js`. Этот файл — только выход сборки, его нельзя коммитить и нельзя копировать в корень репозитория. Если переменная пустая или значение не похоже на DSN, Sentry просто выключен.

Для release-сборки задайте `GC_SENTRY_ENV=production` (по умолчанию `debug`). Имя release в Sentry: `versionName` + имя кэша service worker (например `1.0+moyzal-v67`).

```bash
# Клиентский DSN проекта gymcaptain-android (организация gymcaptain, регион EU).
# Значение не печатать, не коммитить и не сохранять в файлы проекта.
export GC_SENTRY_DSN   # уже задан в текущей оболочке
# export GC_SENTRY_ENV=production   # только для release

npm run build:web
npx cap sync android
cd android && ./gradlew assembleDebug
```

Приватность: `sendDefaultPii=false`, пользователь / email / IP не отправляются, Session Replay и трассировка выключены, консольные и полевые (ui.input) хлебные крошки отбрасываются. Кнопки «Сообщить о проблеме» нет.

### Проверить на телефоне (D-211, дополнение)

В debug-сборке (когда `GC_SENTRY_ENV` не `production`) в консоли удалённой отладки Chrome доступны `__gcSentryTestCrash()` (неперехваченная JS-ошибка) и `__gcSentryTestNativeCrash()` (нативный краш, закрывает приложение). Вызывать только на тестовом телефоне, не с сайта.


## Вход через Google в приложении (D-265)

Google запрещает вход внутри WebView. Поэтому в Android-версии кнопка «Войти через Google» открывает Google во встроенной вкладке браузера (`@capacitor/browser`, Custom Tab). Supabase возвращает на страницу сайта `auth-callback.html` (адрес уже разрешён в Supabase), она передаёт `?code=` в приложение по ссылке `app.gymcaptain://auth-callback` (intent-filter в `AndroidManifest.xml`), приложение само обменивает код на сессию (PKCE, `exchangeCodeForSession`) через `@capacitor/app` `appUrlOpen`. Веб-версия (PWA) не изменилась. Сборка с этим входом: `versionCode` `3`.
